# tgchanreader — дайджест Telegram-каналов

Бот читает каналы вместо вас и по вашему расписанию (от раза в сутки до каждых 3 часов) присылает сводку новых постов.
У каждого пользователя свой список каналов, свои теги, приоритеты и расписание:

* **каждый канал отдельным сообщением** с названием канала в заголовке; перед ними идёт короткая шапка
  с блоком **«Главное»** (3–6 пунктов по всем каналам). Звук уведомления только у шапки;
* **длинные посты сокращаются** нейросетью до 1–3 предложений, к ним идёт ссылка «читать полностью»;
* **канал всегда помещается в одно сообщение**: если за ночь в нём набралось слишком много постов, нейросеть
  выкидывает мелочи, а остальное сжимает до одной строки на пост;
* **реклама пропускается**: маркировка `erid`, `#реклама` и прочие эвристики плюс проверка LLM;
* **посты без текста** (только фото или видео) выводятся строкой «🖼 Только медиа (фото) — открыть пост»;
* у каналов есть **теги** (`новости`, `велосипед`…) и **приоритеты**: сначала каналы с приоритетом 1, потом 2, потом 3…;
* **несколько пользователей**: вы и друзья из `.env`, у каждого свой список каналов. Общий канал читается и
  обрабатывается нейросетью один раз, сколько бы человек на него ни было подписано;
* **расписание в боте** (`/schedule`): любые из слотов 06, 09, 12, 15, 18, 21 — не чаще раза в 3 часа, минимум раз в сутки;
* есть **веб-архив и RSS**: лента дайджестов, лента всех постов и ленты по тегам;
* LLM подключается через **OpenRouter** (по умолчанию) или напрямую: **OpenAI**, **Anthropic Claude**, **Ollama**
  (локально) или любой OpenAI-совместимый API (DeepSeek, Groq, LM Studio, vLLM…).

Пример дайджеста (каналы вымышленные). Каждый блок ниже — отдельное сообщение:

```
📰 Дайджест · 5 ноября 2026, 09:00
Постов: 37 · каналов: 12 · пропущено рекламы: 6

🧭 Главное
• …
```

```
🔴 Городские новости
#новости #город · 4 поста

▫️ 06:15 ✂️ Краткий пересказ длинного поста…
    → читать полностью

▫️ 07:02 Короткий пост целиком
    → оригинал
```

```
🟠 Шумный канал
#новости · 46 постов · сжато, без мелочей

▫️ 01:10 Главная новость одной строкой
▫️ 03:42 🖼 Ещё одна важная новость
▫️ 08:05 …

…и ещё 31 пост поменьше — в канале
```

```
🟡 Вело-клуб
#велосипед · 1 пост

▫️ 08:40 🎬 Только медиа (видео) — открыть пост
```

В сжатом режиме время — это ссылка на пост.

## Как бот читает каналы

Обычный Telegram-бот не может читать чужие каналы. Поэтому есть два источника:

| Режим | Что нужно | Что умеет |
|---|---|---|
| `web` (по умолчанию) | ничего | Читает публичные каналы через веб-превью `t.me/s/<канал>`. Аккаунт не нужен. |
| `telethon` | `TG_API_ID`, `TG_API_HASH`, `TG_SESSION` | Читает от имени **вашего** аккаунта: приватные каналы, каналы без веб-превью, команда `/import` добавляет все ваши подписки разом. |

При `SOURCE=auto` используется Telethon, если заданы переменные `TG_*`, иначе `web`. В режиме Telethon веб-превью
остаётся запасным вариантом. Бот (`BOT_TOKEN`) в обоих режимах нужен только для управления и отправки дайджеста.

## Быстрый старт

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите `BOT_TOKEN`.
2. Получите ключ на [openrouter.ai/keys](https://openrouter.ai/keys).
3. Подготовьте папку:

```bash
mkdir tgchanreader && cd tgchanreader
```

```bash
curl -O https://raw.githubusercontent.com/shevchukma/tgchanreader/main/docker-compose.yml
```

```bash
curl -o .env https://raw.githubusercontent.com/shevchukma/tgchanreader/main/.env.example
```

4. Впишите в `.env` `BOT_TOKEN`, `LLM_API_KEY` и `ADMIN_IDS`. Свой ID можно не искать заранее: запустите контейнер,
   напишите боту `/start`, он ответит вашим ID. Впишите его и перезапустите.
5. Запустите:

```bash
docker compose up -d
```

6. Напишите боту `/start`, добавьте каналы и выберите время рассылки через `/schedule`:

```
/add @example_news новости,город 1
/add https://t.me/example_velo велосипед 3
```

Канал можно добавить и проще: перешлите боту любой пост из него.

Без docker compose:

```bash
docker run -d --name tgchanreader --restart unless-stopped --env-file .env -p 8080:8080 -v $(pwd)/data:/data velikoross/tgchanreader:latest
```

## Пользователи и доступ

* `ADMIN_IDS` — администраторы. Первый в списке — владелец: ему переходят каналы из старых версий и `channels.yml`.
* `ALLOWED_IDS` — друзья. Пользуются ботом наравне с вами, но со своим списком каналов.
* Все остальные получают ответ «⛔ Это приватный бот» с их Telegram ID. Его можно прислать вам, чтобы вы добавили
  человека в `ALLOWED_IDS`.

```env
ADMIN_IDS=123456789
ALLOWED_IDS=222222222,333333333
# необязательно: сколько каналов может добавить друг (0 — без лимита; на админов не действует)
MAX_CHANNELS_PER_USER=0
```

У каждого пользователя свой список каналов, теги, приоритеты, расписание и своя отметка о прочитанном.
Каналы и посты хранятся один раз: если на канал подписаны трое, он скачивается один раз и каждый пост
обрабатывается нейросетью один раз. Сжатие перегруженного канала тоже переиспользуется.

Дайджест приходит всем, кто нажал `/start` и есть в `.env`. Если убрать человека из `.env` и перезапустить
контейнер, ему перестанут приходить дайджесты и перестанут работать его личные ссылки. Его каналы сохранятся.
`/stop` отключает рассылку, каналы при этом не удаляются.
`DIGEST_CHAT_IDS` — дополнительно присылать копию дайджеста владельца в группу.

## Расписание

Каждый пользователь сам выбирает время в боте командой `/schedule`: кнопками включаются слоты
**06:00, 09:00, 12:00, 15:00, 18:00, 21:00** (часовой пояс `TZ`). Есть готовые варианты: «каждые 3 часа»,
«утро, день, вечер», «утро и вечер», «раз в день». Можно и текстом: `/schedule 9,21`.
Чаще раза в 3 часа нельзя, нужен хотя бы один раз в сутки.

`DIGEST_TIMES` в `.env` задаёт только расписание по умолчанию для новых пользователей, например `DIGEST_TIMES=06:00-21:00/3`
или `DIGEST_TIMES=09:00`. Время вне слотов игнорируется.

## Команды бота

| Команда | Описание |
|---|---|
| `/start` / `/stop` | Включить / выключить рассылку (каналы сохраняются) |
| `/add @канал [теги] [приоритет]` | Добавить канал в свой список (или обновить теги/приоритет) |
| `/remove @канал` | Удалить канал из своего списка |
| `/list` | Мои каналы по приоритетам |
| `/tag @канал тег1,тег2` | Задать теги (`/tag @канал -` убирает теги, `/tag` без аргументов выводит все теги) |
| `/priority @канал 1` | Задать приоритет (1 — самый важный) |
| `/pause @канал`, `/resume @канал` | Приостановить / возобновить канал |
| `/schedule` | Когда присылать дайджест |
| `/digest` | Прислать дайджест сейчас; эти посты не попадут в следующий |
| `/preview [тег]` | Показать будущий дайджест, не отмечая посты прочитанными |
| `/rss` | Личные ссылки на веб-архив и RSS |
| `/status` | Мои каналы, расписание, следующий дайджест |

Пересланный боту пост из канала добавляет этот канал в ваш список.

Только для администраторов:

| Команда | Описание |
|---|---|
| `/users` | Пользователи: кто получает дайджест, сколько каналов, кто ещё не нажал `/start` |
| `/import` | Добавить себе все каналы аккаунта Telethon |
| `/llmtest` | Проверить, отвечает ли нейросеть с текущими настройками |
| `/reprocess` | Заново обработать нейросетью посты за последние `MAX_POST_AGE_HOURS` часов |

## Подключение Telethon (приватные каналы, импорт подписок)

1. Зайдите на [my.telegram.org](https://my.telegram.org) → *API development tools* и получите `api_id` и `api_hash`.
2. Сгенерируйте строку сессии (бот спросит телефон, код из Telegram и пароль 2FA, если он есть):

```bash
docker run -it --rm velikoross/tgchanreader:latest python -m tgchanreader.login
```

3. Впишите в `.env` `TG_API_ID`, `TG_API_HASH`, `TG_SESSION` и перезапустите контейнер.
4. В боте выполните `/import`, затем расставьте теги и приоритеты.

> ⚠️ `TG_SESSION` даёт полный доступ к аккаунту. Никому её не передавайте и не коммитьте `.env`.
> Сервис только читает сообщения, ничего не отправляет от вашего имени.

## Нейросети

Все «умные» функции (реклама, сокращение, «Главное за день») идут через один LLM-клиент:

```env
# OpenRouter: любая модель из https://openrouter.ai/models
LLM_PROVIDER=openrouter
LLM_API_KEY=sk-or-v1-...
LLM_MODEL=google/gemini-2.5-flash
```

```env
# Claude напрямую
LLM_PROVIDER=anthropic
LLM_API_KEY=sk-ant-...
LLM_MODEL=claude-haiku-5-5
```

```env
# OpenAI или любой OpenAI-совместимый API
LLM_PROVIDER=openai
LLM_API_KEY=sk-...
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
```

```env
# Локальная Ollama (без ключа)
LLM_PROVIDER=ollama
LLM_BASE_URL=http://ollama:11434/v1
LLM_MODEL=qwen2.5:7b
```

С `LLM_PROVIDER=none` сервис работает и без нейросети: рекламу ловят эвристики, длинные посты обрезаются.
Если нейросеть недоступна, посты ждут в очереди, и бот повторяет попытку при каждом сборе.
Если к моменту дайджеста она так и не ответила, посты обрабатываются упрощённо, и дайджест всё равно приходит.
При ошибке ключа, модели или настроек аккаунта (HTTP 400–404) запросы приостанавливаются на 10 минут,
чтобы не тратить лимиты и не засорять лог. Проверить настройки можно командой `/llmtest`, переобработать посты — `/reprocess`.

### Частые ошибки OpenRouter

* **`No allowed providers are available for the selected model … permits only: xai`**: в
  [настройках OpenRouter](https://openrouter.ai/settings/privacy) ограничен список провайдеров. Разрешите провайдера
  выбранной модели (для `google/*` это Google AI Studio / Vertex) или выберите модель разрешённого провайдера,
  например `x-ai/…`.
* **`No endpoints found matching your data policy`**: включите в тех же настройках использование моделей
  с вашей политикой данных или выберите другую модель.
* **401**: неверный `LLM_API_KEY`. **402**: на балансе OpenRouter закончились деньги.

Посты отправляются в модель пачками (`LLM_BATCH_SIZE`, по умолчанию 8), чтобы экономить запросы.

## Веб-архив и RSS

При `WEB_ENABLED=true` на порту 8080 у каждого пользователя есть личный архив и RSS. Ссылки выдаёт бот
командой `/rss`. В ссылках секретный ключ, поэтому чужие ленты по ним не открыть:

| Адрес | Что |
|---|---|
| `/u/<ключ>/` | Мой архив дайджестов |
| `/u/<ключ>/digest/<id>` | Дайджест в браузере (ссылка «Открыть в браузере» в шапке дайджеста) |
| `/u/<ключ>/rss/digests.xml` | RSS: каждый дайджест — отдельная запись |
| `/u/<ключ>/rss/posts.xml` | RSS: все посты моих каналов без рекламы, длинные сокращены |
| `/u/<ключ>/rss/posts.xml?tag=велосипед` | RSS по моему тегу |
| `/healthz` | Проверка работоспособности |

Если задан `WEB_TOKEN`, по адресу `/?token=...` открывается список пользователей со ссылками на их архивы.
Пропишите внешний адрес в `WEB_BASE_URL`, чтобы ссылки вели куда нужно.

Сервис может работать вообще без бота, только с RSS. Для этого не задавайте `BOT_TOKEN`, а каналы перечислите в
`data/channels.yml` (пример лежит в `channels.example.yml`). Тогда архив и ленты доступны по адресам `/`,
`/rss/digests.xml` и `/rss/posts.xml` (с `?token=...`, если задан `WEB_TOKEN`). Дайджест собирается по `DIGEST_TIMES`.

## Все настройки

Полный список с комментариями лежит в [`.env.example`](.env.example). Основные:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DIGEST_TIMES` | `09:00` | Расписание по умолчанию для новых пользователей: `09:00,21:00` или `06:00-21:00/3`. Каждый меняет своё через `/schedule` |
| `TZ` | `Europe/Moscow` | Часовой пояс |
| `COLLECT_INTERVAL_MINUTES` | `60` | Как часто опрашивать каналы |
| `FIRST_FETCH_HOURS` | `24` | За сколько часов брать посты у только что добавленного канала |
| `SUMMARY_THRESHOLD` | `600` | Посты длиннее (в символах) сокращаются |
| `SUMMARY_MAX_CHARS` | `350` | Желаемая длина пересказа |
| `SHORT_POST_MAX_CHARS` | `800` | Короткие посты обрезаются до этой длины |
| `SKIP_ADS` | `true` | Пропускать рекламу |
| `DIGEST_OVERVIEW` | `true` | Блок «Главное за день» |
| `DIGEST_LANGUAGE` | `русский` | Язык пересказов |
| `DEFAULT_PRIORITY` | `2` | Приоритет новых каналов |
| `ALLOWED_IDS` | — | Друзья: свои списки каналов и расписание |
| `MAX_CHANNELS_PER_USER` | `0` | Лимит каналов у друзей (0 — без лимита) |
| `DIGEST_CHAT_IDS` | — | Дополнительно слать копию дайджеста владельца в эти чаты (группы) |
| `SEND_EMPTY_DIGEST` | `false` | Слать дайджест, даже если новых постов нет |

Данные (SQLite) хранятся в `/data`, это папка `./data` рядом с `docker-compose.yml`.

## Сборка и публикация образа

GitHub Actions (`.github/workflows/docker.yml`) прогоняет тесты и собирает образ для `linux/amd64` и `linux/arm64`.
При пуше в `main` образ публикуется как `velikoross/tgchanreader:latest`, при теге `v1.2.3` — как `1.2.3` и `1.2`.
Для этого в настройках репозитория (*Settings → Secrets and variables → Actions → New repository secret*) добавьте секрет:

* `DOCKERHUB_TOKEN` — токен доступа с [app.docker.com/settings/personal-access-tokens](https://app.docker.com/settings/personal-access-tokens)
  (права *Read & Write*).
* `DOCKERHUB_USERNAME` — необязательно, по умолчанию `velikoross`.

Без токена workflow не падает: образ собирается для проверки, но не публикуется (в сводке будет предупреждение).

Собрать вручную:

```bash
docker build -t velikoross/tgchanreader:latest .
```

```bash
docker push velikoross/tgchanreader:latest
```
